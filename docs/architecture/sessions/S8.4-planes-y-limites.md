# S8.4 — Planes, suscripciones y límites de uso

> **Estado:** pendiente · **Etapa 8 — SaaS y producción** · **Tamaño:** M · **Repos:** faclab-core, faclab-web · **Brechas:** —

## 1. Identificador y título

`S8.4` — Planes, suscripciones y límites de uso

## 2. Objetivo verificable

Existen planes con límites (sucursales, terminales, usuarios, comprobantes por mes, API pública); cada empresa tiene una suscripción con estado; los comandos que crean recursos limitados verifican el plan y el uso mensual de comprobantes se mide y se muestra.

## 3. Problema que resuelve

Sin planes ni límites no se puede vender por suscripción ni controlar el uso.

## 4. Evidencia de la brecha actual

- No existen planes ni suscripciones en el modelo (MULTI_TENANCY.md §10).

## 5. Componentes y archivos que probablemente se modificarán

- `src/platform/` (planes, suscripciones, uso), verificación en comandos de creación, consumo de un evento agregado de uso desde invoicing, pantallas de plan y uso.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- `src/platform/` (S2.1), comandos de creación de sucursales, terminales, usuarios e integraciones.

## 7. Dependencias y sesiones previas

[S2.5](S2.5-sucursales-y-puntos-de-emision.md)

## 8. Tareas concretas en orden

1. Modelar planes y suscripciones (estado: prueba, activa, suspendida, cancelada).
2. Verificar límites en los comandos con error `PLAN_LIMIT_REACHED`.
3. Medir comprobantes por mes (evento agregado desde invoicing) y mostrar el uso.
4. Definir el comportamiento de suscripción suspendida (solo lectura, sin bloquear la emisión de ventas ya hechas).
5. Pantallas de plan y uso para la empresa y administración de planes para la plataforma.

## 9. Criterios de aceptación verificables

- Crear una sucursal más allá del límite responde 409 `PLAN_LIMIT_REACHED`.
- Una empresa suspendida puede consultar pero no crear ventas (prueba).

## 10. Pruebas que deben ejecutarse

- Pruebas unitarias e integración; frontend.
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core

## 11. Riesgos y posibles regresiones

- No bloquear la facturación de ventas ya confirmadas.

## 12. Migraciones, cambios de configuración y despliegue

- Tablas nuevas; plan por defecto para empresas existentes.

## 13. Estrategia de rollback o recuperación

- Desactivar la verificación por configuración.

## 14. Documentación que debe actualizarse

- MULTI_TENANCY.md §10, docs/modules.md.

- Todos los criterios de aceptación se cumplen y las pruebas listadas pasan (en CI si ya existe).
- La documentación indicada está actualizada y este archivo marca *Estado: terminada* con fecha y ramas o PR.
- No quedan secretos en el código, los logs ni la documentación.
