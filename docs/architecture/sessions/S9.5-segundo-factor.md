# S9.5 — Segundo factor (TOTP)

> **Estado:** pendiente · **Etapa 9 — Piloto y endurecimiento** · **Tamaño:** M · **Repos:** faclab-core, faclab-web · **Brechas:** G-86

## 1. Identificador y título

`S9.5` — Segundo factor (TOTP)

## 2. Objetivo verificable

Los ADMIN de cada empresa y los operadores de plataforma entran con contraseña y un código TOTP (RFC 6238), con códigos de recuperación de un solo uso; el alta, la pérdida del dispositivo y su recuperación están documentadas; la consola de plataforma no acepta un login sin segundo factor.

## 3. Problema que resuelve

ASVS nivel 2 exige un segundo factor (6.3.3) y la consola de plataforma ve todas las empresas: una contraseña robada de un operador o de un ADMIN no debe bastar. El usuario lo pidió antes del piloto (2026-11-27).

## 4. Evidencia de la brecha actual

- S-21: no hay segundo factor (SEGURIDAD.md); ASVS 6.3.3 «No cumple» y 6.4.4, 6.5.x «No aplica» hasta tenerlo.
- S-01 (S9.3) mostró que la consola es el objetivo más valioso.

## 5. Componentes y archivos que probablemente se modificarán

- src/auth/ (enrolamiento, verificación, códigos de recuperación, estado del usuario)
- src/platform_console/app/commands/login.py
- faclab-web: enrolamiento con QR, pantalla del código, recuperación
- docs/auth-spec.md, docs/onboarding-guide.md

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- `src/auth/app/commands/login.py` y `select_tenant.py` (el token de selección como paso intermedio)
- `src/platform_console/app/commands/login.py`
- la bitácora (`AuditAction`) y `redact_sensitive` (la semilla nunca en logs)

## 7. Dependencias y sesiones previas

[S9.4](S9.4-sesiones-y-contrasenas.md)

## 8. Tareas concretas en orden

1. Modelo y migración: semilla TOTP cifrada (llave como `SECRET_ENCRYPTION_KEYS`), códigos de recuperación con hash, fecha de enrolamiento.
2. Enrolamiento (QR, confirmación con un código) y verificación con ventana de ±1 paso, sin reutilizar un código ya usado (ASVS 6.5.1), con bloqueo por intentos.
3. Login en dos pasos: contraseña → token intermedio corto → código; obligatorio para ADMIN y operadores, opcional para los demás roles (decisión del usuario).
4. Recuperación: códigos de un solo uso y reseteo del segundo factor por otro ADMIN o por la CLI de plataforma, auditado.
5. Pantallas de web y pruebas e2e del flujo.

## 9. Criterios de aceptación verificables

- Un ADMIN y un operador no pueden entrar sin el código.
- Un código no sirve dos veces y uno vencido se rechaza.
- Reseteo del segundo factor auditado.
- ASVS 6.3.3 pasa a «Cumple».

## 10. Pruebas que deben ejecutarse

- Las pruebas nuevas de cada tarea.
- faclab-web: `npm run test:e2e` del flujo de login con segundo factor.
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core

## 11. Riesgos y posibles regresiones

- Bloquear a un ADMIN que pierde el dispositivo: el reseteo por otro ADMIN o por la plataforma debe existir antes de exigirlo.
- Reloj del servidor: TOTP depende de la hora (NTP en el VPS).

## 12. Migraciones, cambios de configuración y despliegue

- Migración con las tablas del segundo factor.
- Variable para exigirlo por rol.

## 13. Estrategia de rollback o recuperación

- Variable que deja de exigirlo sin borrar los enrolamientos.
