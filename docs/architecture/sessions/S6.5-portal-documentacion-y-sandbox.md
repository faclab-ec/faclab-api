# S6.5 — Portal de integraciones, documentación y sandbox

> **Estado:** pendiente · **Etapa 6 — API pública** · **Tamaño:** M · **Repos:** faclab-web, faclab-core · **Brechas:** G-72

## 1. Identificador y título

`S6.5` — Portal de integraciones, documentación y sandbox

## 2. Objetivo verificable

Los administradores gestionan clientes de integración y webhooks desde faclab-web; existe una documentación pública con guías y ejemplos en curl, Python y JavaScript que se ejecutan en CI contra un sandbox con datos ficticios y facturación en el ambiente de pruebas del SRI.

## 3. Problema que resuelve

Sin portal, documentación ni sandbox, cada integración requiere soporte manual.

## 4. Evidencia de la brecha actual

- No existen portal ni documentación pública (G-72).

## 5. Componentes y archivos que probablemente se modificarán

- faclab-web: feature `integrations` (clientes, scopes, sucursales, secretos, uso, webhooks, entregas).
- Core: publicación de la documentación pública (Scalar con OpenAPI público y guías), script de datos de sandbox.
- Ejemplos ejecutables en `docs/public-api/examples/` y job de CI.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- Endpoints de S6.2–S6.4; PUBLIC_API.md §10.

## 7. Dependencias y sesiones previas

[S6.3](S6.3-api-v1.md), [S6.4](S6.4-webhooks.md)

## 8. Tareas concretas en orden

1. Construir las pantallas del portal con permisos de administración.
2. Escribir las guías: autenticación, sincronización de catálogo y stock, ventas desde ecommerce, recepción de facturas por webhook.
3. Escribir los ejemplos y un job que los ejecute contra un entorno de sandbox.
4. Script para crear una empresa de sandbox con datos ficticios.

## 9. Criterios de aceptación verificables

- Un integrador sin acceso al código completa la guía de punta a punta solo con la documentación (prueba con alguien externo o simulada paso a paso).
- Los ejemplos pasan en CI.

## 10. Pruebas que deben ejecutarse

- E2E del portal; job de ejemplos.
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL

## 11. Riesgos y posibles regresiones

- El sandbox no debe compartir datos con producción: entorno o empresas separadas.

## 12. Migraciones, cambios de configuración y despliegue

- Subdominio de sandbox (D-9).

## 13. Estrategia de rollback o recuperación

- Ocultar el portal por permiso.

## 14. Documentación que debe actualizarse

- `docs/public-api/`, README de faclab-web.

## 15. Condición para declarar la sesión terminada

- Todos los criterios de aceptación se cumplen y las pruebas listadas pasan (en CI si ya existe).
- La documentación indicada está actualizada y este archivo marca *Estado: terminada* con fecha y ramas o PR.
- No quedan secretos en el código, los logs ni la documentación.
- Lo que quedó fuera de alcance está anotado como pendiente en este archivo o en ROADMAP.md.
