# S9.1 — Pruebas E2E del flujo completo

> **Estado:** pendiente · **Etapa 9 — Piloto y endurecimiento** · **Tamaño:** M · **Repos:** faclab-web, faclab-core, faclab-invoicing, faclab-infra · **Brechas:** G-77

## 1. Identificador y título

`S9.1` — Pruebas E2E del flujo completo

## 2. Objetivo verificable

Una suite E2E corre contra servicios reales (core, invoicing, Kafka, PostgreSQL y el ambiente de pruebas del SRI o un simulador fiel) y cubre: login con empresa, apertura de turno, venta con presentación y lista de precios, factura autorizada con RIDE, devolución con nota de crédito, cierre de caja y conciliación sin discrepancias.

## 3. Problema que resuelve

Las pruebas E2E actuales usan el backend simulado; nadie verifica que el sistema completo funcione unido.

## 4. Evidencia de la brecha actual

- Playwright usa `tests/e2e/support/mockApi.ts` (G-77).

## 5. Componentes y archivos que probablemente se modificarán

- faclab-web: proyecto Playwright `full-stack`; faclab-infra: compose de pruebas E2E; datos semilla deterministas.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- Suite Playwright actual, compose de staging (S8.1), simulador del SRI si existe.

## 7. Dependencias y sesiones previas

[S4.5](S4.5-nota-de-credito.md), [S8.1](S8.1-stack-de-produccion-en-vps.md)

## 8. Tareas concretas en orden

1. Crear un entorno efímero con todos los servicios y datos semilla.
2. Escribir los escenarios del objetivo con esperas por estados asíncronos (factura, nota de crédito).
3. Decidir cuándo usar el SRI de pruebas real y cuándo un simulador (estabilidad del CI) y documentarlo.
4. Ejecutar la suite en CI de forma programada (por ejemplo, cada noche) y bajo demanda.

## 9. Criterios de aceptación verificables

- La suite pasa en CI y detecta una regresión inyectada a propósito en el contrato de eventos.

## 10. Pruebas que deben ejecutarse

- La suite E2E nueva.
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-invoicing: `npm run lint && npm run typecheck && npm test`
- faclab-infra: `docker compose config -q` y levantar los servicios afectados

## 11. Riesgos y posibles regresiones
