# S8.5 — Onboarding de empresas y consola de plataforma

> **Estado:** pendiente · **Etapa 8 — SaaS y producción** · **Tamaño:** L · **Repos:** faclab-core, faclab-web, faclab-invoicing · **Brechas:** —

## 1. Identificador y título

`S8.5` — Onboarding de empresas y consola de plataforma

## 2. Objetivo verificable

Un operador de la plataforma da de alta una empresa y su administrador desde una consola; el administrador completa un asistente (perfil fiscal, certificado, sucursales, puntos de emisión, terminales, usuarios, importación inicial, secuenciales iniciales) y al final el readiness de facturación queda en verde en el ambiente de pruebas del SRI.

## 3. Problema que resuelve

Incorporar una ferretería hoy requeriría comandos manuales y conocimiento técnico.

## 4. Evidencia de la brecha actual

- Solo existe la CLI de alta de S2.1 y la configuración dispersa en varias pantallas.

## 5. Componentes y archivos que probablemente se modificarán

- Consola de plataforma (rol de plataforma) en faclab-web, asistente de onboarding, endpoints de plataforma en el core, readiness en invoicing.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- CLI de alta (S2.1), organización (S2.5), facturación multiempresa (S2.8), importación (S5.8), readiness de invoicing.

## 7. Dependencias y sesiones previas

[S8.4](S8.4-planes-y-limites.md), [S2.8](S2.8-facturacion-multiempresa.md), [S5.8](S5.8-importacion-masiva.md)

## 8. Tareas concretas en orden

1. Consola de plataforma: listar, crear, suspender empresas; ver estado de facturación y uso.
2. Asistente de onboarding por pasos con validaciones y posibilidad de retomar.
3. Verificación final: readiness de facturación y una factura de prueba en el ambiente de pruebas.
4. Paso para pasar a producción del SRI (cambio de ambiente explícito con confirmación).

## 9. Criterios de aceptación verificables

- Una empresa nueva queda lista para facturar en pruebas siguiendo solo el asistente.
- El paso a producción exige confirmación y queda auditado.

## 10. Pruebas que deben ejecutarse

- E2E del asistente; pruebas de integración de endpoints de plataforma.
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core
- faclab-invoicing: `npm run lint && npm run typecheck && npm test`

## 11. Riesgos y posibles regresiones

- Datos de certificados: el asistente nunca muestra contraseñas guardadas.

## 12. Migraciones, cambios de configuración y despliegue

- Sin migraciones de esquema mayores.

## 13. Estrategia de rollback o recuperación

- Ocultar la consola por permiso.

## 14. Documentación que debe actualizarse

- Guía de onboarding para operadores, MULTI_TENANCY.md §9.

## 15. Condición para declarar la sesión terminada

- Todos los criterios de aceptación se cumplen y las pruebas listadas pasan (en CI si ya existe).
- La documentación indicada está actualizada y este archivo marca *Estado: terminada* con fecha y ramas o PR.
- No quedan secretos en el código, los logs ni la documentación.
- Lo que quedó fuera de alcance está anotado como pendiente en este archivo o en ROADMAP.md.
