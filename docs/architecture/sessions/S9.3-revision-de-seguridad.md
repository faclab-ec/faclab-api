# S9.3 — Revisión de seguridad y aislamiento

> **Estado:** pendiente · **Etapa 9 — Piloto y endurecimiento** · **Tamaño:** M · **Repos:** faclab-core, faclab-invoicing, faclab-web, faclab-infra · **Brechas:** —

## 1. Identificador y título

`S9.3` — Revisión de seguridad y aislamiento

## 2. Objetivo verificable

Se completa una revisión basada en el estándar de verificación de seguridad de aplicaciones de OWASP (ASVS) nivel 2 sobre los cuatro repos y el entorno de staging, con escaneo de dependencias y de imágenes en CI, pruebas de acceso cruzado entre empresas sobre la API interna y pública, y un informe con hallazgos priorizados y corregidos o planificados.

## 3. Problema que resuelve

Antes de recibir datos reales de clientes hay que verificar sistemáticamente la seguridad y el aislamiento.

## 4. Evidencia de la brecha actual

- No hay escaneo de dependencias ni revisión de seguridad formal.

## 5. Componentes y archivos que probablemente se modificarán

- CI (escaneo de dependencias e imágenes), correcciones puntuales, informe en `docs/architecture/`.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- Suites de aislamiento (S2.4), auth (S1.4, S6.1, S6.2), configuración de Caddy y secretos (S8.1).

## 7. Dependencias y sesiones previas

[S6.3](S6.3-api-v1.md), [S8.1](S8.1-stack-de-produccion-en-vps.md)

## 8. Tareas concretas en orden

1. Agregar escaneo de dependencias (pip-audit, npm audit o equivalente) y de imágenes (por ejemplo, Trivy) al CI.
2. Recorrer la lista ASVS nivel 2 aplicable y registrar el cumplimiento.
3. Pruebas manuales y automatizadas de acceso cruzado entre empresas, escalamiento de permisos, SSRF en webhooks, cargas de archivos y límites.
4. Corregir hallazgos críticos y altos; planificar el resto como sesiones nuevas.

## 9. Criterios de aceptación verificables

- Sin hallazgos críticos ni altos abiertos; informe publicado; escaneos en CI.

## 10. Pruebas que deben ejecutarse

- Escaneos en CI y pruebas de seguridad documentadas.
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-invoicing: `npm run lint && npm run typecheck && npm test`
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core
- faclab-infra: `docker compose config -q` y levantar los servicios afectados

## 11. Riesgos y posibles regresiones

## 12. Migraciones, cambios de configuración y despliegue
