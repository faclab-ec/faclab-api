# S7.3 — Observabilidad del frontend

> **Estado:** pendiente · **Etapa 7 — Observabilidad completa** · **Tamaño:** M · **Repos:** faclab-web, faclab-core · **Brechas:** G-69

## 1. Identificador y título

`S7.3` — Observabilidad del frontend

## 2. Objetivo verificable

faclab-web envía trazas de carga y de llamadas `fetch`/XHR con `traceparent` hacia los dominios propios, errores no controlados y web vitals al endpoint OTLP público; las trazas del navegador se continúan en el core e invoicing; los mensajes de error muestran el id de solicitud.

## 3. Problema que resuelve

Los errores de interfaz que afectan operaciones comerciales son invisibles.

## 4. Evidencia de la brecha actual

- Sin OTel web, Sentry ni web vitals; `ErrorBoundary` solo hace `console.error` (G-69).

## 5. Componentes y archivos que probablemente se modificarán

- faclab-web: inicialización del SDK web, `ErrorBoundary`, notificaciones de error con `requestId`.
- Core e invoicing: CORS que permita `traceparent` y `tracestate`.
- Proxy o Collector: endpoint `/otlp` con límites.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- `faclab-web/src/App.tsx`, `components/ErrorBoundary.tsx`, `shared/lib/http/httpClient.ts`, `shared/lib/getErrorMessage.ts`.

## 7. Dependencias y sesiones previas

[S1.5](S1.5-observabilidad-base.md)

## 8. Tareas concretas en orden

1. Agregar el SDK web con instrumentación de documento y fetch/XHR limitada a los dominios propios.
2. Reportar errores no controlados y del `ErrorBoundary` sin datos de formularios.
3. Registrar web vitals agregados por ruta.
4. Mostrar el `requestId` en los mensajes de error.
5. Ajustar CORS en core e invoicing y el endpoint `/otlp` en el entorno local.

## 9. Criterios de aceptación verificables

- Una venta desde el navegador produce una traza que empieza en el navegador y continúa en el core (verificación en SigNoz local).
- Un error de interfaz aparece en SigNoz con ruta y versión de la aplicación, sin datos personales.

## 10. Pruebas que deben ejecutarse

- Pruebas unitarias de la inicialización y del ErrorBoundary; E2E sin regresiones.
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL

## 11. Riesgos y posibles regresiones

- Tamaño del bundle: cargar el SDK de forma diferida y medir.

## 12. Migraciones, cambios de configuración y despliegue

- Configuración del endpoint OTLP público.

## 13. Estrategia de rollback o recuperación

- Desactivar el SDK por configuración.

## 14. Documentación que debe actualizarse

- OBSERVABILITY.md §9.3, README de faclab-web.
