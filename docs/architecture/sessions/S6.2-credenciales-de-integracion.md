# S6.2 — Credenciales de integración con OAuth 2.0 *client credentials*

> **Estado:** pendiente · **Etapa 6 — API pública** · **Tamaño:** M · **Repos:** faclab-core · **Brechas:** G-72

## 1. Identificador y título

`S6.2` — Credenciales de integración con OAuth 2.0 *client credentials*

## 2. Objetivo verificable

Un administrador crea clientes de integración con scopes, sucursales permitidas y entorno; `POST /api/oauth/token` emite tokens con `tid`, `azp`, `scope` y `bids`; los secretos se guardan como hash, se rotan y se revocan; cada uso queda registrado.

## 3. Problema que resuelve

No hay forma segura de que un sistema externo se autentique sin usar la cuenta de una persona.

## 4. Evidencia de la brecha actual

- No existe ningún concepto de API key ni cliente de máquina a máquina (G-72).

## 5. Componentes y archivos que probablemente se modificarán

- Módulo `src/integrations/` (clientes, secretos con hash, scopes, sucursales, uso), endpoint `/api/oauth/token`, administración en `/api/admin/integrations`.
- `require_permission` y un `require_scope` equivalente para principales de servicio.
- Auditoría de escrituras con actor `integration`.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- `src/auth/` (tokens, permisos), `src/audit/` (S3.5), `src/organization/` (S2.5).

## 7. Dependencias y sesiones previas

[S6.1](S6.1-jwt-asimetrico-y-jwks.md), [S2.5](S2.5-sucursales-y-puntos-de-emision.md), [S3.5](S3.5-bitacora-de-auditoria.md)

## 8. Tareas concretas en orden

1. Modelar el cliente de integración (prefijo visible, hash del secreto, scopes, sucursales, IPs permitidas, entorno, estado, último uso).
2. Implementar el endpoint de token con autenticación básica del cliente y validación de scopes solicitados.
3. Mapear scopes a permisos existentes y limitar por plan (S8.4 si existe; si no, dejar el punto de extensión).
4. Rotación (dos secretos) y revocación inmediata (cache de 60 s como máximo).
5. Registro de uso agregado por día y auditoría de escrituras.

## 9. Criterios de aceptación verificables

- Un cliente sin el scope `sales:write` recibe 403 al crear ventas (prueba).
- Un cliente restringido a una sucursal no puede operar en otra.
- Revocar un cliente invalida sus tokens en menos de 60 s.
- El secreto nunca se devuelve después de crearlo ni se registra en logs.

## 10. Pruebas que deben ejecutarse

- Pruebas unitarias e integración, incluida la suite de aislamiento.
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL

## 11. Riesgos y posibles regresiones

- Un scope mal mapeado abre permisos: revisar la tabla de mapeo con pruebas exhaustivas.

## 12. Migraciones, cambios de configuración y despliegue

- Tablas nuevas con RLS.

## 13. Estrategia de rollback o recuperación

- Desactivar el endpoint de token por configuración.

## 14. Documentación que debe actualizarse

- PUBLIC_API.md §3 (marcar implementado), docs/auth-spec.md.
