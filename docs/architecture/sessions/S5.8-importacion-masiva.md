# S5.8 — Importación masiva de datos iniciales

> **Estado:** pendiente · **Etapa 5 — Operación de ferretería** · **Tamaño:** M · **Repos:** faclab-core, faclab-web · **Brechas:** F-05

## 1. Identificador y título

`S5.8` — Importación masiva de datos iniciales

## 2. Objetivo verificable

Un administrador importa desde CSV (o XLSX) productos con presentaciones y precios, clientes, proveedores y saldos iniciales de inventario con costo; la importación valida todo antes de escribir, informa errores por fila y es idempotente.

## 3. Problema que resuelve

Una ferretería tiene miles de artículos y clientes: sin importación, el onboarding es inviable.

## 4. Evidencia de la brecha actual

- No existe importación masiva (F-05).

## 5. Componentes y archivos que probablemente se modificarán

- Módulo `src/imports/` (trabajos de importación, validación, ejecución por lotes en el worker), plantillas descargables, frontend con carga y reporte de errores.

## 6. Archivos o módulos que deben inspeccionarse antes de editar

- Comandos de creación de catálogo, clientes, proveedores y ajustes; worker (S3.4); auditoría (S3.5).

## 7. Dependencias y sesiones previas

[S5.2](S5.2-unidades-y-presentaciones.md), [S5.3](S5.3-listas-de-precios.md)

## 8. Tareas concretas en orden

1. Definir las plantillas y columnas obligatorias, y publicarlas como archivos descargables.
2. Implementar la carga (archivo guardado por empresa), validación completa y reporte por fila sin escribir nada.
3. Ejecutar la importación confirmada por lotes en el worker usando los comandos existentes; saldos iniciales como ajustes auditados con costo.
4. Idempotencia por clave natural (SKU, identificación) con opción de actualizar o saltar.
5. Pantalla de importación con progreso y descarga de errores.

## 9. Criterios de aceptación verificables

- Importar 10.000 productos termina en un tiempo razonable medido y documentado.
- Un archivo con errores no escribe nada y devuelve el detalle por fila.
- Repetir la misma importación no duplica registros.

## 10. Pruebas que deben ejecutarse

- Pruebas de validación, ejecución y volumen (archivo grande sintético).
- faclab-core: `make lint && make typecheck && .venv/bin/python -m pytest tests/ -q`
- faclab-core: `make test-integration` si cambian modelos, migraciones, consultas SQL o flujos con PostgreSQL
- faclab-web: `npx tsc --noEmit && npm run lint && npm test`
- faclab-web: `npm run test:e2e` si cambian flujos de interfaz; `OPENAPI_URL=http://localhost:3000/openapi.json npm run check:contract` si cambia el contrato con el core

## 11. Riesgos y posibles regresiones

- Archivos grandes: limitar tamaño y procesar en streaming.

## 12. Migraciones, cambios de configuración y despliegue

- Tablas de trabajos de importación con RLS.

## 13. Estrategia de rollback o recuperación

- Revertir; las importaciones hechas quedan como datos normales (auditadas).

## 14. Documentación que debe actualizarse

- Guía de importación para usuarios en `docs/`, MULTI_TENANCY.md §9.
